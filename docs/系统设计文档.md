# 基于 Spring Boot 的蜂场养殖与蜂蜜溯源管理系统设计与实现（企业级升级版）

## 摘 要

随着消费者对蜂产品品质与来源关注度的不断提升，传统蜂场依赖人工台账记录、蜂蜜溯源信息缺失的管理方式已难以满足行业规范化、透明化发展的需求。本文设计并实现了一套基于 Spring Boot + Vue 前后端分离架构的蜂场养殖与蜂蜜溯源管理系统，并在初版基础上完成了面向蜂场实际经营的企业级升级。后端采用 JDK 17、Spring Boot 3.2.5、Spring Security 6、MyBatis-Plus 3.5.6 与 MySQL 8 进行数据持久化与业务处理，前端使用 Vue 3.4、Element Plus 2.7、Pinia、Vue Router 4 与 Vite 5 构建交互界面，并以 ECharts 5.5 完成数据可视化。

系统覆盖蜂场分区、蜂箱档案、蜜源地、蜂王与蜂群、蜂箱巡检、饲喂、分蜂繁育、病害防治与用药、摇蜜采收、装瓶生产、质检、溯源码与二维码、扫码日志、多仓库库存台账与流水、客户与销售出库、供应商与采购、成本费用、统计报表、数据看板与预警中心等完整业务，实现了从蜂群养殖到蜂蜜产出、再到产品出库与公开溯源的全流程数据记录与质量追溯。系统保留休药期校验、批次号自动生成、库存联动、出库审核等关键机制，新增仓库维度库存、采购审核事务、Excel 导出、公开溯源扫码日志与设备识别、五类预警聚合、四类统计报表等企业级能力。

数据库由初版 26 张表扩展至 36 张表（系统表 sys_* 10 张、业务表 biz_* 26 张），导入演示数据后全库约 2371 条记录，数据时间跨度为 2025-01 至 2026-10-03，采收集中在每年 4—8 月花期，呈明显季节性。经本地构建、功能与接口测试、公网部署实测，系统运行稳定、功能完整，数据自洽（成品库台账期末 963 瓶 = 装瓶入库 2786 − 出库 1823），有效提升了蜂场养殖经营管理效率，为蜂蜜产品提供了可信的溯源依据，对蜂业信息化与品质管控具有实际应用价值。

**关键词**：蜂场养殖；蜂蜜溯源；Spring Boot；Vue 3；RBAC；二维码；统计报表；预警中心

## 1 绪论

### 1.1 研究背景

蜂业是现代农业的重要组成部分，蜂蜜、蜂王浆、蜂花粉等产品兼具营养价值与经济价值。然而，我国蜂场长期存在以下问题：

- **养殖过程记录缺失**：蜂箱位置、群势、蜂王信息、巡检、饲喂、病害与用药情况多依赖纸质记录，易丢失、难查询；
- **溯源链条断裂**：消费者无法获知蜂蜜的蜜源地、采收时间、质检结果、用药情况，扫码后缺乏访问数据沉淀，难以辨别产品真伪与品质；
- **质量安全存在隐患**：用药后未经过休药期即摇蜜，可能造成药物残留；蜂箱异常、库存不足等待办缺乏统一提醒；
- **库存与经营管理粗放**：产品装瓶、入库、出库缺乏分仓库统一台账，采购、成本费用、销售与毛利缺乏量化统计，账实不符、经营决策缺数据支撑。

构建一套覆盖"养殖—巡检饲喂—采收—生产—质检—溯源—库存—采购—销售—成本—报表"全链路的信息化管理系统，并在此基础上提供数据看板、预警与经营分析能力，成为提升蜂场管理水平与产品可信度的迫切需求。

### 1.2 研究意义

- **对蜂场管理者**：实现养殖、生产、仓储、采购、成本数据的数字化、规范化，通过看板与报表量化经营，提升管理效率，降低人工记录与对账成本；
- **对一线作业人员**：巡检、饲喂、分蜂、采收、装瓶、出入库均有结构化记录，操作留痕、责任到人；
- **对消费者**：通过扫码即可查看完整溯源信息，每一次访问都被记录，增强消费信心；
- **对监管与行业**：提供可追溯、可统计的数据基础，推动蜂业质量管控与品牌建设。

### 1.3 研究内容

本文围绕蜂场养殖与蜂蜜溯源业务，在初版系统基础上完成企业级升级，主要工作包括：

1. 重构数据看板，建设预警中心与四类统计报表；
2. 扩展仓库、巡检、饲喂、分蜂、供应商、采购、扫码日志、成本费用等新业务模块并提供完整 CRUD；
3. 引入 Apache POI 实现 8 类业务数据的 Excel 导出；
4. 为公开溯源增加扫码日志与设备类型识别，库存表增加仓库维度；
5. 完成数据库由 26 张表到 36 张表的扩展、全量数据导入、本地构建与公网部署验证。

重点解决采购审核与出库审核的库存事务一致性、休药期校验、库存分仓自洽、溯源链路聚合与扫码留痕、预警规则聚合、经营成本毛利核算等关键问题。

## 3 系统需求分析

### 3.1 可行性分析

- **技术可行性**：Spring Boot 3、Vue 3、MyBatis-Plus、POI、ECharts 均为成熟技术，社区活跃、资料丰富，开发与构建工具链完善；
- **经济可行性**：系统基于开源技术栈，无需商业授权，单台云服务器即可部署，成本低；
- **操作可行性**：前端界面基于 Element Plus，查询、表格、分页、弹窗交互统一，具备基础计算机操作能力的人员即可使用。

### 3.2 角色分析（RBAC）

系统基于角色的访问控制（RBAC），结合蜂场实际岗位设置 6 类角色，对应 6 个内置用户：

| 角色 | 编码 | 主要职责 |
|---|---|---|
| 系统管理员 | admin | 全部功能，用户/角色/菜单/字典/日志管理 |
| 蜂场场长 | manager | 全场业务查看与审批，基础档案、采购/出库审核 |
| 养殖员 | farmer | 蜂箱、蜂王、蜂群、巡检、饲喂、分蜂、病害、用药记录 |
| 生产员 | producer | 摇蜜采收、装瓶、质检录入 |
| 库管员 | warehouse | 多仓库库存台账、出入库、采购入库、蜂具管理 |
| 销售员 | sales | 客户管理、出库单、溯源码查看、扫码日志 |

权限通过"用户—角色—菜单/按钮"三级模型控制：菜单控制页面可见性，按钮权限（如 `hive:add`、`report:export`）通过 `v-hasPermi` 指令控制操作按钮。后端接口使用 `@PreAuthorize("@ss.hasPermi('xxx')")` 校验，Excel 导出接口同样走权限注解控制。

### 3.3 功能需求

系统功能划分为 12 大模块：

1. **基础档案**：蜂场分区、蜂箱档案、蜜源地管理；
2. **养殖管理**：蜂王档案、蜂群记录，以及本次升级新增的蜂箱巡检、饲喂记录、分蜂繁育；
3. **病害防治**：病害登记、用药登记（含休药期）；
4. **采收生产**：摇蜜采收、装瓶生产、质检录入；
5. **溯源管理**：溯源码生成、二维码、公开溯源页、扫码日志；
6. **仓储管理**：仓库档案、库存台账（按仓库）、出入库流水；
7. **采购管理**：供应商档案、采购单与采购明细、采购审核入库；
8. **销售管理**：客户管理、出库单与审核；
9. **成本费用**：人工、饲料、药品、蜂具、包装、其他费用登记；
10. **预警中心**：休药期、库存不足、蜂箱异常、待质检、待审核五类预警聚合与处理；
11. **统计报表**：产量、销售、库存、成本毛利四类报表，支持筛选、维度切换、图表与导出；
12. **系统管理**：用户、角色、菜单、部门、字典、操作日志、登录日志，以及重构后的数据看板。

### 3.4 非功能需求

- **安全性**：密码 BCrypt 加密存储；接口经 JWT 鉴权；按钮级权限控制；公开溯源接口仅暴露只读聚合数据，不泄露内部账号信息；
- **可靠性**：装瓶入库、出库审核、采购审核等关键业务使用数据库事务，保证台账与流水一致；
- **易用性**：统一的查询、表格、分页、弹窗交互模式，看板与报表图表直观；
- **可维护性**：分层清晰（Controller/Service/Mapper/Entity），实体统一继承基类，代码规范；
- **可审计性**：公开溯源每次访问记录扫码日志（溯源码、IP、UA、设备类型），业务操作留痕；
- **可扩展性**：模块化设计，新增业务模块（如巡检、饲喂、采购、成本）均按同一 CRUD + 分页 + 权限范式扩展。

## 4 系统总体设计

### 4.1 系统架构设计

系统采用经典的前后端分离三层架构，生产环境经 nginx 反向代理对外：

```
┌──────────────────────────────────────────────┐
│   浏览器 / 消费者手机 (Vue 3 + Element Plus)   │
│  登录页 / 主布局 / 业务页面 / 看板 / 报表       │
│  公开溯源页 / 二维码 PNG                        │
└───────────────┬──────────────────────────────┘
                │  HTTP / JSON（Bearer JWT）
        ┌───────▼────────┐
        │   Nginx (80)    │  静态资源 + /api 反向代理
        └───────┬────────┘
                │ 127.0.0.1:8090
┌───────────────▼──────────────────────────────┐
│     Spring Boot 应用 (端口 8090, /api)         │
│  Controller 控制层（参数校验、路由、权限）       │
│  Service 业务层（事务、业务规则、编号生成）      │
│  Mapper 持久层（MyBatis-Plus）                 │
│  Security：JWT 过滤器 / UserDetailsService     │
│  POI 导出 / ZXing 二维码 / 扫码日志切面         │
└───────────────┬──────────────────────────────┘
                │ JDBC（仅 127.0.0.1:3306）
        ┌───────▼────────┐
        │   MySQL 8.0    │
        │   bee_farm 库   │
        └────────────────┘
```

生产环境中后端与 MySQL 仅监听 127.0.0.1，8090 与 3306 不对公网开放，仅 80 端口经 nginx 对外提供服务。

### 4.2 后端分层与包结构

后端包根为 `com.beefarm`，按业务模块分包：

### 4.4 统一响应与异常处理

- 后端统一返回结构 `R<T>`：`{ code, msg, data }`，分页返回 `TableDataInfo<T>`：`{ code, msg, rows, total }`；
- 业务异常通过 `BusinessException` 抛出，由 `GlobalExceptionHandler` 统一捕获并返回友好提示；
- 前端 Axios 响应拦截器统一处理 `code`：200 放行，401 自动登出回登录页，其他错误弹出提示。

### 4.5 认证与授权流程

1. 用户提交账号密码，后端 `AuthenticationManager` 校验通过后生成 JWT 返回；
2. 前端将 token 存入本地，后续请求在 Header 携带 `Authorization: Bearer <token>`；
3. `JwtAuthenticationFilter` 解析并校验 token，构造 `LoginUser` 放入安全上下文；
4. 前端通过 `/auth/info` 获取角色与权限标识，通过 `/auth/routers` 获取动态菜单；
5. 接口使用 `@PreAuthorize("@ss.hasPermi('xxx')")` 控制，页面按钮使用 `v-hasPermi` 控制。

### 4.6 动态路由与顶级单页菜单

后端返回的菜单树中，目录（M）与菜单（C）按 `component` 字符串映射为前端组件。对于"预警中心"这类顶级单页菜单，前端统一用系统主布局（Layout）作为父级包裹，将其自身作为子路由注册，使其既出现在侧边栏一级菜单中，又能在主内容区正常渲染，避免裸页面无布局的问题。页面组件通过 `import.meta.glob('@/views/**/*.vue')` 收集并映射，最后 `router.addRoute` 动态注入。

## 5 数据库设计

### 5.1 数据库设计原则

- 采用统一的表前缀：系统表 `sys_`、业务表 `biz_`；
- 业务表普遍包含审计字段（`create_by`、`create_time`、`update_by`、`update_time`、`remark`）与逻辑删除字段 `deleted`（`0` 存在、`1` 删除）；
- 关键编号（批次号、溯源码、采购/出库单号）建立唯一索引；
- 关联字段建立普通索引，不使用物理外键（便于扩展与数据迁移）；
- 本次升级后，库存台账与库存流水统一增加 `warehouse_id` 仓库维度，实现分仓核算。

### 5.2 实体基类设计

为减少重复字段，系统设计三个实体基类，所有新实体均显式标注 `@TableName("对应表名")`：

| 基类 | 字段 | 适用场景 |
|---|---|---|
| `BaseEntity` | id、createBy、createTime、updateBy、updateTime、remark | 无逻辑删除的表（如 sys_role、sys_dept） |
| `AuditEntity` | 继承 BaseEntity，增加 deleted（`@TableLogic`） | 绝大多数业务表（含本次新增的仓库、巡检、饲喂、分蜂、供应商、采购、预警、成本费用等） |
| `CreateOnlyEntity` | id、createBy、createTime、deleted | 仅创建、业务字段不更新的表（如 biz_trace_code、biz_scan_log；扫码计数除外） |

审计字段由 `MetaObjectHandlerConfig` 在插入/更新时自动填充，操作人通过 `SecurityUtils` 获取；逻辑删除由 MyBatis-Plus `@TableLogic` 统一过滤。

## 6 核心业务流程设计

### 6.1 摇蜜采收与休药期校验

摇蜜登记是溯源链条的起点。系统在创建采收记录时执行：

1. 生成采收批次号（HS + 日期 + 流水）；
2. **休药期校验（关键质量控制）**：查询该蜂箱所有用药记录，若存在 `safe_date`（安全采收日期）晚于本次 `harvest_date` 的记录，说明仍处于休药期内，立即抛出 `BusinessException` 拦截摇蜜，提示"该蜂箱处于休药期，安全采收日期为 X，禁止摇蜜"；
3. 校验通过后保存采收记录，状态为"待加工"，并可据此生成休药期预警。

### 6.2 装瓶生产与库存联动

装瓶是连接采收与成品的关键环节，使用数据库事务保证一致性：

1. 选择"待加工"的采收批次，填写产品名称、规格、装瓶数量、生产日期、保质期；
2. 生成产品批次号（CP + 日期 + 流水），保存产品批次；
3. 将来源采收批次状态更新为"已装瓶"；
4. 按"仓库（成品库）+ 产品名称 + 规格"查询库存台账：存在则增加库存数量，不存在则新建台账；
5. 写入一条"入库"库存流水，记录操作后库存；
6. 全部操作在同一事务内提交，任一失败整体回滚。

### 6.3 质检录入

质检人员对产品批次录入检测项目（蔗糖、羟甲基糠醛、水分、淀粉酶值等）、检测结果、指标值；保存质检记录的同时，将产品批次 `qc_status` 回写为"合格/不合格"，并作为"待质检"预警的清除依据。

### 6.4 溯源码、二维码与扫码日志

1. 选择产品批次，生成溯源码（TR + 时间戳 + 随机数），拼接 `qr_url = https://example.invalid/trace/<码>`；
2. 使用 ZXing 3.5.3 将溯源 URL 编码为 PNG 二维码图片输出；
3. 消费者扫码或访问公开链接进入公开溯源页。

### 6.5 公开溯源链路聚合与扫码留痕

公开溯源接口按溯源码反向聚合全链路数据，形成"从蜂箱到餐桌"信息：

```
溯源码 → 产品批次 → 采收批次 → 蜂箱 / 蜜源地
                    → 质检记录（N）
                    → 用药记录（N）
```

该接口不要求登录。每次访问执行：

1. 聚合返回产品、采收、蜜源地与蜂箱、质检、用药信息；
2. 溯源码 `scan_count` 自增，更新 `last_scan_time`；
3. **新增**：向 `biz_scan_log` 写入一条扫码日志，记录溯源码、访问时间、客户端 IP、User-Agent，并依据 UA 推断设备类型（手机/微信/浏览器）。

### 6.6 出库审核与库存扣减

出库采用"先建单、后审核"两步流程：

1. 销售员创建出库单，选择客户，添加明细（产品批次、数量、单价），汇总总数量与总金额，状态"待审核"；
2. 审核时在事务内逐明细处理：校验成品库库存是否充足，不足则抛异常并整体回滚；扣减库存台账、更新产品批次状态；写入"出库"库存流水；
3. 审核通过后单据状态变为"已出库"，"待审核"预警相应清除。

库存自洽实测：成品库台账期末 **963** 瓶 = 装瓶入库 **2786** − 出库 **1823**，差额为 0。

### 6.7 采购审核与入库事务（新增）

采购流程与出库审核对称设计：

1. 库管/采购员创建采购单，选择供应商与入库仓库，添加明细（物料、规格、数量、单价、单位），汇总总数量与总金额，状态"待审核"；
2. 审核时在**同一数据库事务**内逐明细处理：按"仓库 + 物料名称 + 规格"查询或新建库存台账，增加库存数量；写入一条"入库"库存流水（biz_type=1），记录操作后库存；
3. 审核通过后采购单状态变为"已入库"。该事务参照出库审核事务实现，保证采购入库台账与流水一致。

### 6.8 预警规则聚合（新增）

预警中心按规则从业务数据中聚合 5 类预警，支持"按规则重新生成"：

| 类型 | 触发规则 |
|---|---|
| 休药期 | 存在用药记录的 `safe_date` 晚于当前日期（仍在休药期内） |
| 库存不足 | 库存台账当前 stock ≤ warn_stock 预警库存 |
| 蜂箱异常 | 巡检记录存在 abnormal 异常情况，或蜂王状态异常 |
| 待质检 | 产品批次 qc_status = 0（未检） |
| 待审核 | 出库单/采购单 status = 0（待审核） |

预警列表支持查看、按类型筛选，处理操作将状态置为"已处理"并记录处理人与处理时间；可随时按上述规则重新生成未处理预警。

### 7.3 前端关键实现

- **Axios 封装**：`baseURL` 为 `/api`，自动携带 token，401 自动登出；
- **动态路由**：路由守卫收集 `@/views/**/*.vue` 组件映射后端路由，顶级单页菜单（预警中心）用 Layout 包裹后作为子路由注册；
- **菜单与权限**：递归渲染侧边栏，`v-hasPermi` 控制按钮显隐；
- **看板与报表**：ECharts 5.5 渲染趋势、环形、饼图、双轴图，支持时间范围与维度切换；
- **导出交互**：各列表页"导出"按钮携带当前筛选条件请求 `/export`，浏览器下载 `.xlsx`；
- **公开溯源页**：独立无布局页面，展示聚合信息并展示二维码。

### 7.4 典型页面交互

业务页面统一采用"查询表单（含日期范围）+ 工具栏（新增/导出）+ 数据表格 + 分页 + 新增/编辑弹窗 + 删除确认"的交互模式；预警中心、报表页采用"筛选 + 列表/图表 + 处理/导出"模式，保证全系统操作一致性。

## 9 总结与展望

### 9.1 工作总结

本文完成并企业级升级了一套基于 Spring Boot 3.2.5 + Vue 3.4 前后端分离的蜂场养殖与蜂蜜溯源管理系统，主要工作包括：

1. 完成需求分析、RBAC 角色权限设计与总体架构设计；
2. 数据库由 26 张表扩展至 36 张表（系统表 10、业务表 26），覆盖养殖作业、仓储、采购、成本、预警与扫码访问全链路；

系统实现了从蜂群养殖到蜂蜜产出、再到销售出库与公开溯源的全流程数字化记录、经营统计与质量追溯，有效提升了蜂场管理效率与产品可信度。

### 9.2 不足与展望
